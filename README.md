# 食品风险批次追召

本项目保存食品风险批次追召所需的领域上下文、校验契约和一个可运行的追召领域服务，
便于服务端功能围绕真实业务参与方展开。数据均为演示用虚构内容。

## 参与方

市场监管人员（抽样/处置/复审/上级协调）、生产企业、中间商、直播平台渠道

## 模型与谱系（`src/food_recall/model.py`）

原料批 → 生产批 → 多个包装批（贴不同标签）→ 出货单 → 渠道与销售主体（可跨地区）。

- 一个生产批可拆成多个包装批，拆分合计不得超过产量；
- 同一包装批可分多张出货单，出货合计不得超过包装量；
- 抽样、封存、复检申请/决定、处置、跨区协调、平台回执都是**只追加的证据记录**，
  每条带时间、责任人、对象与数量。

## 服务规则（`src/food_recall/service.py`）

| 业务要求 | 实现 |
| --- | --- |
| 不只按品牌查封，区分合格货与风险货 | 抽检超标/原料异常扩散到整批；仅标签异常只追涉事包装批；`affected_quantity` 计算真实受影响数量 |
| 一批拆多包装批、多渠道合并回报 | 谱系建档 + 出货单台账，中间商现场处置与平台回执并入同一守恒视图 |
| 退货/销毁/放行/未追回与出货量守恒 | 每张出货单恒等式：退货+销毁+复检放行+未追回=出货量，超额登记直接拒绝 |
| 相同平台回执不重复扣减 | 回执号+载荷一致时幂等返回 |
| 回执内容矛盾暂停该渠道结案 | 同号内容矛盾或累计超量 → 渠道置 held，新回报拒收，`resolve_hold` 核查后解除 |
| 抽检人员不能批准自己的复检 | 批准人与抽样人相同即拒绝；复检决定不可重复作出 |
| 跨地区流向上级协调 | 跨辖区出货单须 `coordinate` 后才允许渠道结案 |
| 停机后复检期限与催办继续 | 期限为日期值按自然日计算，`overdue_rechecks` 在恢复当日即产生催办，逾期决定留痕 |
| 打开一批货看到全貌 | `overview`：风险依据、实际去向、已控制数量（封存+追回）、催办、渠道状态、证据链 |

## 测试

```bash
python3 -m unittest discover -s tests -v
```

`tests/test_recall.py` 覆盖谱系拆分、风险扩散、守恒、回执幂等/矛盾、复检回避、
跨区协调、结案条件与批次总览共 20 个用例。

## 编译

```bash
python3 -m compileall -q src tests
```

## 命令行

```bash
# 领域资料校验摘要
python3 -m src.food_recall.context fixtures/context.json

# 核桃油追召场景演示（输出批次办案总览 JSON）
python3 -m src.food_recall.demo
```
